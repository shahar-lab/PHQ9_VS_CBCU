Build Log: Parameter Recovery for bradley_terry_beta_tau_per

Built 2026-09-10 via the ShaharLab Malka / Sharon / Tomer pipeline (Code Writer + Code Reviewer subagents). This document records how simulation/bradley_terry_beta_tau_per_recovery/ came to be, for future reference.

Why this study exists

bradley_terry_beta_tau_per.R (generative code) and bradley_terry_beta_tau_per.stan (fitting model) already existed in models/, but no parameter recovery study had been run for this model — unlike its siblings bradley_terry_beta and bradley_terry_beta_tau, each of which has a matching simulation/<model>_recovery/ folder. This was confirmed by checking for that folder before starting; it did not exist.

Approved specification

Design20 simulated subjects × 100 trials each, 15-item pool (CBC-U), 2 items offered per trial
Ground truthGroup-level hyperparameters fixed at specific values (see "Post-build change" below); per-subject beta, tau, key_decay, rho, u drawn from those, matching the hierarchical structure exactly
Simulation wiringsim.block() (unmodified) looped over 20 subjects in the recovery pipeline; combined Stan-ready data assembled there, including first_trial_in_block
Fitcmdstanr, 4 chains, 1000 warmup / 1000 sampling
CompareRecovered (posterior mean) vs. true for every free parameter and hyperparameter
RepetitionSingle simulate → fit → compare run

4FAILFixed via facet_wrap(~variable, scales = "free"), giving each hyperparameter its own facet/axes. New finding: facets were missing the required explicit four-tick-mark axis breaks.
5FAILFour-tick breaks added per facet via a four_breaks() helper. New finding: the per-facet Pearson-r/label computation used lapply/do.call(rbind, ...) without clear necessity (coding-rules discourage apply-family use absent a clear need), and left a dead unused lims variable in that block.
6FAILReplaced with a straight-line dplyr::group_by() |> summarise() pipe (orchestrator edit, reviewer-verified). This surfaced the deeper, real issue: facet_wrap(scales = "free") lets each facet's x and y ranges diverge independently, which breaks the meaning of the slope-1 diagonal reference line (true vs. recovered should be directly comparable within a facet). coord_equal() alone only fixes the aspect ratio, not the actual range.
7PASSFixed by anchoring each facet's x and y to an identical, padded [min, max] range via invisible geom_blank() points (covering both true and recovered values per variable) — forcing square, matched ranges per facet while keeping facets independent from each other, with no new package dependency. Reviewer confirmed the mechanism actually achieves this and found no further issues.
ASSUMED decisions surfaced during the build (specification was silent, agent made a defensible default; carried forward without further objection):
  • The 8 group-level hyperparameters are shown on one combined, faceted scatter plot (colour-coded by variable) rather than as 8 separate plot files, since the spec said "one scatter plot per parameter" without specifying whether group-level hyperparameters count individually or as a set.
  • Because those 8 hyperparameters are not co-scaled, per-facet trend lines, per-facet Pearson r, and per-facet axis ranges are computed independently per variable rather than pooled across all 8.

Post-build changes

Changes made after the review loop closed, outside the Writer/Reviewer process (direct edits, at the user's request):

DateChange
2026-09-10main.R line 23 (source(.../simulated_data.R)) errored on first run because artifacts_dir and output_dir did not exist on disk yet — saveRDS() inside simulated_data.R needs the target folder to already exist. 2026-09-10Group-level hyperparameters switched from randomly sampled (drawn fresh from the Stan model's own priors on every run) to fixed values, at the user's request, so the same ground truth is used every run. Chosen within each prior's plausible range (not at the tails):
  • mu_log_beta = 0.5, sigma_log_beta = 0.3 — per-subject beta (choice sensitivity) centered around exp(0.5) ≈ 1.65 with modest spread
  • mu_tau = 0, sigma_tau = 1 — per-subject tau (burden/no-choice threshold) centered at 0
  • mu_logit_key_decay = 1, sigma_key_decay = 0.5 — per-subject key_decay centered around plogis(1) ≈ 0.73 (a meaningful, non-trivial decay rate, not near 0 or 1)
  • mu_rho = 1, sigma_rho = 0.5 — per-subject rho (perseveration bump) clearly positive and non-trivial
Updated in code/simulated_data.R and summary.md.
2026-09-10First actual run hit a runtime error in code/plot_group_recovery.R: summarise(range_val = range_pad(...)) failed because range_pad() returns 2 values (min and max) per group, and dplyr::summarise() requires exactly 1 row per group per column. Fixed by switching that call from summarise() to reframe(), which allows multi-row-per-group output; the surrounding logic (per-facet square anchor points via geom_blank()) is otherwise unchanged.
2026-09-10Second runtime error in the same file: facet_wrap(~variable, scales = "free") combined with coord_equal() is not supported by ggplot2 — a fixed aspect ratio cannot coexist with per-facet free scales, and always errors ("facet_wrap() can't use free scales with coord_cartesian() with a fixed ratio argument"). This was missed in review since the plot was never actually rendered before sign-off. Fixed by removing coord_equal(); the geom_blank() anchor points still force each facet's x and y to share an identical [min, max] range (the property that actually matters for the diagonal reference line), independent of panel aspect ratio.
2026-09-10After a real run, the group-level plot turned out to be visually misleading even though it rendered correctly: with only 1 true/1 recovered point per facet, the old range_pad() zoomed each facet's axes to just c(true_val, recovered_val), so every facet auto-scaled to its own recovery error — a 6% miss (mu_log_beta: true 0.50, recovered 0.53) and a much larger miss (sigma_rho: true ≈0.50, recovered ≈0.14) both ended up looking similarly far from the diagonal, since each facet's zoom level was different. Fixed by anchoring each facet's range to the true value's own scale instead — [min(0, true_val), max(0, true_val)] padded by half the true value's magnitude — so distance from the diagonal now reflects actual recovery error consistently across all 8 hyperparameters, not each facet's self-relative zoom.

How to run it

Open and source main.R. First run compiles the Stan model (can take a minute), then samples with 4 chains. After running, check fit$diagnostic_summary() in the console for divergences, treedepth hits, low E-BFMI, or Rhat > 1.01 before trusting the recovery plots in output/. Fill in summary.md's "Findings / Summary" section with what you observe.
